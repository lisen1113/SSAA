# 修复可选配件在报价清单中的显示问题

## 问题分析

通过代码分析，我发现可选配件在报价清单中显示错误的原因：

1. **配件添加按钮缺少必要属性**：
   - 当前配件添加按钮只包含 `data-accessory`、`data-name` 和 `data-price` 属性
   - 缺少 `data-id`（产品编码）和 `data-config`（配置信息）属性

2. **配件添加逻辑使用错误信息**：
   - 使用 `accessory-${accessoryId}` 作为产品编码，而不是实际的配件编码
   - 使用固定的 "标准配置" 作为配置信息，而不是配件的实际配置

3. **报价单显示格式问题**：
   - 配件在报价单中的显示格式与主机产品相同，但配件应该有其特定的显示格式

## 解决方案

### 1. 修改配件添加按钮

为所有配件的添加按钮添加 `data-id` 和 `data-config` 属性，确保包含完整的配件信息：

```html
<button class="px-3 py-1 bg-primary text-white text-xs rounded-md hover:bg-primary-dark add-accessory" 
        data-accessory="1" 
        data-id="1E4-00007" 
        data-name="USB-C Travel Hub" 
        data-config="Srfc USB-C Travel HubCM SC ChnSimp China Hdwr Commercial Black China Only" 
        data-price="889">
    添加
</button>
```

### 2. 修改配件添加到报价单的逻辑

更新 `addAccessoryButtons` 的点击事件处理逻辑，使用正确的配件信息：

- 使用 `this.dataset.id` 获取正确的产品编码
- 使用 `this.dataset.name` 获取正确的产品名称
- 使用 `this.dataset.config` 获取正确的配置信息

### 3. 优化配件在报价单中的显示

确保配件在报价单中显示的格式正确，包含完整的产品编码、产品名称和配置信息，与主机产品的显示格式区分开。

## 实施步骤

1. **更新配件添加按钮**：为所有14个配件的添加按钮添加缺失的 `data-id` 和 `data-config` 属性
2. **修改配件添加逻辑**：更新 `addAccessoryButtons` 的点击事件处理函数，使用正确的配件信息
3. **测试验证**：确保配件添加到报价单后显示正确的产品编码、名称和配置
4. **生成报价测试**：测试生成的报价文件中配件信息是否正确显示

## 预期结果

修复后，当用户添加配件到报价单时：
- 报价清单中配件的产品编码将显示为正确的编码（如 "1E4-00007"）
- 产品名称将显示为正确的名称（如 "USB-C Travel Hub"）
- 配置信息将显示为正确的配置（如 "Srfc USB-C Travel HubCM SC ChnSimp China Hdwr Commercial Black China Only"）
- 生成的报价文件中配件信息也将正确显示

这样，配件信息就会按照用户提供的内容在报价清单中正确显示，与主机产品的显示格式保持一致但使用正确的配件信息。
